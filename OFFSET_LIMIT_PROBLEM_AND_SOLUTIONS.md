# Проблема: Ограничение Offset API TrendAgent

**Дата:** 2026-02-08  
**Статус:** 🚨 КРИТИЧЕСКАЯ ПРОБЛЕМА

---

## 📊 Обнаруженная Проблема

При полном парсинге с `--limit=10000` все типы объектов остановились на **~344 объектах**:

| Тип | Получено | Ожидалось (по донору) | % Охвата |
|-----|----------|----------------------|----------|
| Parkings | **416** | ~3,644 | **11.4%** ⚠️ |
| Houses | **344** | ~1,023 | **33.6%** ❌ |
| Plots | **344** | ~2,370 | **14.5%** ❌ |
| Commercial | **344** | ~1,771 | **19.4%** ❌ |

### Почему 344?

**API TrendAgent имеет жесткое ограничение: `max_offset ≈ 344`**

```bash
GET /api/v4_29/blocks/search/?offset=0&count=40    → 40 объектов ✅
GET /api/v4_29/blocks/search/?offset=40&count=40   → 40 объектов ✅
GET /api/v4_29/blocks/search/?offset=300&count=40  → 40 объектов ✅
GET /api/v4_29/blocks/search/?offset=344&count=40  → 0 объектов ❌
```

После достижения `offset=344`, API перестает возвращать новые данные, даже если объектов больше.

---

## 💡 Решения

### Решение 1: Фильтрация по Районам (Рекомендуется)

**Идея:** Разбить запросы по районам Санкт-Петербурга

**Преимущества:**
- Каждый район имеет < 344 объектов
- Простая реализация
- Покрывает все объекты

**Реализация:**

```php
// В ParseCommand добавить
private array $spbRegions = [
    'admiralteyskiy',
    'vasiloostrovskiy',
    'vyborgskiy',
    'kalininskiy',
    'kirovskiy',
    'kolpinskiy',
    'krasnogvardeyskiy',
    'krasnoselskiy',
    'kronshtadtskiy',
    'kurortnyy',
    'moskovskiy',
    'nevskiy',
    'petrogradskiy',
    'petrodvortsovyy',
    'primor skiy',
    'pushkinskiy',
    'frunzenskiy',
    'tsentralnyy',
];

private function parseByRegions(string $type): array
{
    $totalProcessed = 0;
    
    foreach ($this->spbRegions as $region) {
        $this->info("Парсинг региона: {$region}");
        
        $offset = 0;
        while (true) {
            $params = [
                'city' => $this->region,
                'region' => $region,  // НОВЫЙ ПАРАМЕТР
                'count' => 100,
                'offset' => $offset,
            ];
            
            $data = $this->apiClient->{'get' . ucfirst($type)}($params);
            $items = $data['data'] ?? [];
            
            if (empty($items)) {
                break;
            }
            
            // Сохранение...
            $totalProcessed += count($items);
            $offset += 100;
            
            if ($offset >= 344) {
                break; // Перейти к следующему региону
            }
        }
    }
    
    return ['processed' => $totalProcessed, 'errors' => 0];
}
```

**Необходимо:**
1. Обновить методы в `TrendAgentApiClient` для поддержки параметра `region`
2. Обновить `ParseCommand` для использования региональной фильтрации

### Решение 3: Комбинированная Фильтрация

**Идея:** Если один район все еще содержит > 344 объектов, использовать комбинацию фильтров

**Пример:**

```php
// Район + Статус
$params = [
    'region' => 'nevskiy',
    'status' => 1,  // Строится
    ...
];

// Район + Застройщик
$params = [
    'region' => 'nevskiy',
    'builder' => 'pik',
    ...
];
```

### Решение 5: Сортировка + Дедупликация (Экспериментальное)

**Идея:** Получить разные наборы данных с разной сортировкой

**Реализация:**

```php
$sortOptions = [
    ['sort' => 'price', 'sort_order' => 'asc'],
    ['sort' => 'price', 'sort_order' => 'desc'],
    ['sort' => 'deadline', 'sort_order' => 'asc'],
    ['sort' => 'name', 'sort_order' => 'asc'],
];

$allIds = [];
foreach ($sortOptions as $sortOption) {
    $params = array_merge(['city' => 'spb', ...], $sortOption);
    $data = $this->apiClient->getHouses($params);
    
    foreach ($data['data'] as $item) {
        $id = $item['_id'];
        if (!in_array($id, $allIds)) {
            $allIds[] = $id;
            // Сохранить объект...
        }
    }
}
```

**Проблема:** Не гарантирует 100% покрытие

## 🛠️ Альтернативные Подходы

### Подход A: Парсинг Checkerboard (Для Квартир)

Для квартир уже используется двухуровневая логика:
1. Получить комплексы
2. Для каждого комплекса получить квартиры через checkerboard

Это обходит ограничение offset для комплексов.

### Подход B: Прямой Скрейпинг HTML

Если API не предоставляет нужных фильтров, можно:
1. Парсить HTML страницы донора
2. Извлекать списки объектов
3. Для каждого объекта делать API запрос по ID

**Проблемы:**
- Медленнее
- Требует обработки HTML
- Зависит от структуры страниц

### Подход C: Использование GraphQL/Альтернативных Endpoints

Возможно, существуют другие API endpoints, которые не имеют ограничения offset:
- `/api/v4_29/search/all`
- `/api/v4_29/objects/list`
- GraphQL endpoint

**Требует исследования.**
