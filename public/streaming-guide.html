Streaming Guide (SSE)

Real-time AI responses with Server-Sent Events NEW v1

Overview

The streaming endpoint allows you to receive AI responses in real-time as they are generated, instead of waiting for the complete response. This is perfect for:

  • ✅ Better UX - Users see immediate feedback
  • ✅ Long responses - Progress indication for lengthy generations
  • ✅ Reduced latency - Start processing results immediately
  • ✅ Interactive applications - Chat interfaces, live editors
🔑 Key Differences:
• /api/v1/ai/process - Returns complete response at once (JSON)
• /api/v1/ai/stream - Streams response token-by-token (SSE)

Endpoint

POST https://api.siteaccess.ru/api/v1/ai/stream

Headers

Header Value Required
Authorization Bearer {token} ✅ Yes
Content-Type application/json ✅ Yes
X-Trace-ID Custom trace ID (optional) ❌ No

Request Body

Same as /api/v1/ai/process:

{
  "provider": "gemini",
  "model": "gemini-1.5-pro",
  "prompt": "Write a short story about AI",
  "parameters": {
    "temperature": 0.7,
    "max_tokens": 1000
  }
}

Response Format (Server-Sent Events)

Event Types

Event Description When
start Stream started Beginning of response
token New token received Each word/token generated
done Stream completed End of response
error Error occurred On any error

Client Examples

JavaScript (Browser)

const token = 'your-bearer-token';

const eventSource = new EventSource(
  'https://api.siteaccess.ru/api/v1/ai/stream',
  {
    headers: {
      'Authorization': `Bearer ${token}`,
      'Content-Type': 'application/json'
    },
    method: 'POST',
    body: JSON.stringify({
      provider: 'gemini',
      model: 'gemini-1.5-pro',
      prompt: 'Write a short story about AI'
    })
  }
);

// Handle start event
eventSource.addEventListener('start', (e) => {
  const data = JSON.parse(e.data);
  console.log('Stream started:', data.request_id);
});

// Handle token events
eventSource.addEventListener('token', (e) => {
  const data = JSON.parse(e.data);
  document.getElementById('output').innerHTML += data.content;
});

// Handle completion
eventSource.addEventListener('done', (e) => {
  const data = JSON.parse(e.data);
  console.log('Stream completed:', data.usage);
  eventSource.close();
});

// Handle errors
eventSource.addEventListener('error', (e) => {
  const data = JSON.parse(e.data);
  console.error('Stream error:', data.detail);
  eventSource.close();
});

JavaScript (Fetch API)

async function streamAI() {
  const response = await fetch('https://api.siteaccess.ru/api/v1/ai/stream', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${token}`,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      provider: 'gemini',
      model: 'gemini-1.5-pro',
      prompt: 'Write a short story about AI'
    })
  });

  const reader = response.body.getReader();
  const decoder = new TextDecoder();

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    const chunk = decoder.decode(value);
    const lines = chunk.split('\n');

    for (const line of lines) {
      if (line.startsWith('data: ')) {
        const data = JSON.parse(line.substring(6));
        
        if (data.content) {
          // Token received
          document.getElementById('output').innerHTML += data.content;
        } else if (data.usage) {
          // Stream completed
          console.log('Usage:', data.usage);
        }
      }
    }
  }
}

Python

import requests
import json

def stream_ai():
    url = 'https://api.siteaccess.ru/api/v1/ai/stream'
    headers = {
        'Authorization': f'Bearer {token}',
        'Content-Type': 'application/json'
    }
    data = {
        'provider': 'gemini',
        'model': 'gemini-1.5-pro',
        'prompt': 'Write a short story about AI'
    }

    with requests.post(url, headers=headers, json=data, stream=True) as response:
        for line in response.iter_lines():
            if line:
                line = line.decode('utf-8')
                
                if line.startswith('event: '):
                    event = line.split(': ')[1]
                    
                elif line.startswith('data: '):
                    data = json.loads(line[6:])
                    
                    if event == 'start':
                        print(f"Stream started: {data['request_id']}")
                    
                    elif event == 'token':
                        print(data['content'], end='', flush=True)
                    
                    elif event == 'done':
                        print(f"\n\nUsage: {data['usage']}")
                    
                    elif event == 'error':
                        print(f"\nError: {data['detail']}")
                        break

stream_ai()

Best Practices

1. Handle Connection Timeouts

SSE connections can stay open for up to 1 hour. Implement reconnection logic:

eventSource.onerror = () => {
  console.log('Connection lost, reconnecting...');
  setTimeout(() => connectStream(), 5000);
};

2. Buffer Incomplete Text

Tokens may arrive mid-word. Buffer until you receive a complete sentence:

let buffer = '';
eventSource.addEventListener('token', (e) => {
  buffer += JSON.parse(e.data).content;
  if (buffer.endsWith('.') || buffer.endsWith('!') || buffer.endsWith('?')) {
    renderSentence(buffer);
    buffer = '';
  }
});

3. Close Connections Properly

Always close the EventSource when done:

eventSource.addEventListener('done', () => {
  eventSource.close();
});

// Also handle component unmount (React example)
useEffect(() => {
  return () => eventSource.close();
}, []);
⚠️ Important:
• Streaming uses more server resources - use only when needed
• Rate limits still apply to streaming requests
• Connection timeout is 3600 seconds (1 hour)
• For short responses, consider using /api/v1/ai/process instead

Error Handling

Errors are sent as RFC 7807 Problem Details:

event: error
data: {"type":"https://api.siteaccess.ru/docs/errors/rate-limit-exceeded","title":"Rate Limit Exceeded","status":429,"detail":"Daily request limit of 100 exceeded","trace_id":"550e8400-...","timestamp":"2026-02-06T16:00:00Z"}

Response Headers

Header Description
Content-Type text/event-stream
Cache-Control no-cache
Connection keep-alive
X-Trace-ID Request trace ID
X-Request-ID Unique request identifier

Performance Considerations

  • Bandwidth: Streaming may use more bandwidth due to event overhead
  • Server Resources: Keeps connection open longer
  • Client Processing: Requires handling partial responses
  • Use Case: Best for responses > 200 tokens or interactive UIs

When to Use Streaming vs. Standard

Use Streaming When... Use Standard When...
• Long responses (> 500 tokens) • Short responses (< 100 tokens)
• Chat interfaces • API integrations
• Real-time editing • Batch processing
• User feedback is critical • Complete response needed immediately
