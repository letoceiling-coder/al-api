# 🔍 Диагностика проблем с парсером

## Проблема: Парсер не запускается

### Возможные причины:

1. **PID файл не очищается после завершения**
   - После завершения парсера PID файл остается, и система считает, что парсер все еще запущен
   - **Решение:** Исправлено - добавлена автоматическая очистка PID файла после завершения

2. **Команда не найдена**
   - Проверьте, что команда `trendagent:parse` зарегистрирована
   - **Решение:** Выполните `php artisan list | grep trendagent`

3. **Права доступа**
   - Парсер не может создать файлы в `storage/trendagent/`
   - **Решение:** `chmod -R 775 storage/trendagent`

4. **Процесс уже запущен**
   - Проверьте через `ps aux | grep trendagent:parse`
   - **Решение:** Остановите старый процесс или очистите PID файл

---

## ✅ Исправления

### 1. Автоматическая очистка PID файла

Добавлен метод `clearParserPid()` который:
- Проверяет, запущен ли процесс по PID
- Если процесс завершен, удаляет PID файл и связанные файлы
- Вызывается автоматически после завершения парсинга

### 2. Улучшенная обработка статистики

- Пропуск типа 'images' (другая структура)
- Безопасный доступ к ключам массива
- Вывод только при наличии данных

## 🔧 Диагностика на сервере

```bash
# 1. Проверить, запущен ли парсер
ps aux | grep "trendagent:parse"

# 2. Проверить PID файл
cat storage/app/parser_pid.txt

# 3. Проверить логи
tail -f storage/logs/parser_*.log

# 4. Очистить PID файл вручную (если нужно)
rm -f storage/app/parser_pid.txt
rm -f storage/app/parser_log.txt
rm -f storage/app/parser_started_at.txt

# 5. Проверить права доступа
ls -la storage/trendagent/
chmod -R 775 storage/trendagent/
chown -R www-data:www-data storage/trendagent/
```
