# 🔄 Обновление на сервере: Решение проблемы

## Проблема

На сервере есть локальные изменения, которые мешают обновлению из Git. Файл `DeployTrendagentCommand.php` не существует, потому что изменения еще не были обновлены через `git pull`.

## ✅ Решение

### Вариант 1: Сохранить изменения и обновить (рекомендуется)

```bash
# На сервере
cd /var/www/AL

# Сохранить текущие изменения
git stash

# Обновить из Git
git pull

# Вернуть сохраненные изменения (если нужно)
git stash pop
```

### Вариант 2: Откатить локальные изменения (если они не нужны)

```bash
# На сервере
cd /var/www/AL

# Откатить все изменения
git reset --hard HEAD

# Обновить из Git
git pull
```

### Вариант 3: Закоммитить изменения и обновить

```bash
# На сервере
cd /var/www/AL

# Добавить все изменения
git add -A

# Закоммитить
git commit -m "Server local changes"

# Обновить из Git (может потребоваться merge)
git pull
```

---

## После обновления

```bash
# Очистить кеш Laravel
php artisan clear-compiled
php artisan config:clear
php artisan cache:clear

# Проверить, что команда существует
php artisan list | grep deploy

# Выполнить развертывание
php artisan deploy:trendagent

# Проверить права доступа
chown -R www-data:www-data public/trendagent
chmod -R 755 public/trendagent
```

## 📝 О файлах на сервере

Судя по `git status`, на сервере есть:

1. **Modified files** - измененные файлы (возможно, локальные правки)
2. **Deleted files** - удаленные файлы (старые версии в `public/assets/`)
3. **Untracked files** - новые файлы, не добавленные в Git

**Рекомендация:** Используйте `git stash` для сохранения изменений, затем `git pull` для обновления, затем выполните развертывание.

---

## ⚠️ Важно

Если на сервере есть важные локальные изменения, которые нужно сохранить:
1. Сначала сделайте бэкап: `cp -r /var/www/AL /var/www/AL.backup`
2. Затем используйте `git stash` для сохранения изменений
3. После обновления проверьте, что все работает
4. При необходимости верните изменения: `git stash pop`
